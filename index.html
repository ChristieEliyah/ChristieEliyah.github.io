设计文档摘要

项目定位：UE5 FPS 训练靶场 Demo，参考 COD 新手教程关卡设计，纯蓝图开发。在 XL_FPSPack 资产包基础上做系统整合与定制。

核心系统：

  • 玩家：移动、视角、开镜灵敏度。输入统一走 Enhanced Input，不混用旧输入系统。
  • 武器：基类管逻辑、子类管数据。换弹交给动画通知，不另写计时器。
  • 射击反馈：射线判定命中后按物理材质分流，配弹壳抛掷、弹孔贴花与音效。

走近上车 → 驾驶 → 炮塔瞄准（64s）

行走 → 走进触发区自动上车 → WASD 驾驶（质量 9000 / 质心 −100）→ 炮塔瞄准。录制环境是编辑器 PIE，右下为弹药 HUD。

在已有的 FPS Demo 上塞了一辆能开的挑战者 2，目的只有一个：搞清楚"重车感"到底是哪几个参数给的。

实机运行画面（UE5 编辑器）

车长视角驾驶画面：前景为玩家操控的挑战者坦克（炮塔 / 车长塔 / 天线），左后方是作为对照的第二辆坦克，中央绿色圆环为瞄准准星，右下为弹药 HUD。右侧大纲面板可见本场景由 Tank_CurrentSpawner、Tank_Base_C、BP_UI 与关卡光照体系共同构成。

物理用 Chaos Vehicles：WheeledVehiclePawn 做父类，轮子是两对隐藏的物理轮，外面套一层履带外观。整车按真车 1.0548 缩放对齐到车长 8.3m，轮子半径 74cm 是从车高反推出来的离地间隙。项目原本没开这套配置，得先启插件再给物理加子步进，否则车会陷进地面。

输入是独立的一套映射上下文，靠"被占据 / 被取消占据"切换。不这么做，坦克的油门会和角色的 WASD 打架——这是我踩过的坑，改了两天才想明白问题不在节点连错。

相机在车后 8.75m、上方 5.76m、俯角 12°。这个位置试了三版：贴太近看不见履带和炮塔，太远又没有重量感；俯角低于 10° 时看不出炮塔朝哪，高于 15° 地面被压扁、距离判断会失准。

交互是走近触发区自动上车，E 键下车。下车时要把角色挪到车侧——直接放原地会被车体挤住。

三个参数决定它的性格：整车质量 9000（起步和刹车的惯性全在这上面）、质心 Z 偏移 −100（压住重心，急转不翻）、引擎转速上限 4500（刻意压极速，让节奏像坦克而不是跑车）。

验证没靠感觉。同一个弯道、同一入弯速度跑两遍：质心 +150 时急转必翻，−100 时稳定通过，两段录屏摆在一起看。翻车那一下我才确认，手感是参数组合出来的，不是"调到对了"。

没做完的：履带没有独立受力，炮塔是恒定 40°/s（真车有加速段），炮弹用了简化弹道，命中伤害也没接。这些留到下一版。

OpenGL 射击小游戏 Demo

计算机图形学的课设：C++ + OpenGL 从零写一个第一人称射击，没有引擎。
玩家在盒子靶场里移动、瞄准、打移动的小球，血量和计分都在界面上。

渲染管线自己搭：Assimp 加载模型，着色器全部手写 GLSL（球、枪、粒子、房间、阴影、太阳），Phong 光照 + 阴影映射 + 透明度混合。

代码按职责拆成几块：Model / Shader / World 管资源与着色器编译，BallManager 管小球的生成销毁，Camera 管第一人称视角，Player / Main 跑状态机和主循环。拆成这样是因为第一版全塞在 main 里，改一个光照参数要翻两百行。
